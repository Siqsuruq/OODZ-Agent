Requirements

The agent has been tested on Linux, Windows, and FreeBSD. To run the agent, you will need:

  • Tcl 9.0 or newer
  • Tcl TLS package
  • Tcl Thread package 3.0 or newer
  • Tcllib packages: http, json, json::write, and fileutil
  • Twapi (needed for colorful output under Windows)

The repository includes inifile, tConfClass, tLogger, and zesty.

Check packagesshell
tclsh <<'EOF'
foreach package {Tcl Thread tls http json json::write fileutil} {
    puts "$package [package require $package]"
}
EOF

Configuration

The main configuration format uses INI files. If your first question is "why not JSON or another format?", then this agent is probably not for you.

Create your private configuration file, restrict its permissions to your user, and then edit it:

Linuxshell
cp conf/conf.example.ini conf/conf.ini
chmod 600 conf/conf.ini
Windowspowershell
Copy-Item conf\conf.example.ini conf\conf.ini

The file looks smth like this, and contains placeholders and conservative defaults that you need to edit:

Technical & Contextual Notes

Required Config Options

The example configuration file is mostly self-explanatory, but a few settings are required:

  • LLM.provider - Set this to deepseek or ollama.
  • LLM.url - The base endpoint address for your API calls.
  • LLM.api_key - Your private authorization key for the chosen provider.
  • LLM.model - The specific AI model name to use.
  • Workspace.root - The project folder where the agent operates; the agent will try to stay inside this folder ;)
  • Workspace.instructions - The Markdown file containing specific instructions for the agent.
  • Runner.enabled - Set to true or false to permit the agent to execute Tclsh, Fossil, or other system binaries.

Local Ollama

Ollama uses the same OpenAI-compatible client. Choose a locally installed model that supports tool calling.

conf/conf.iniini
[LLM]
provider = ollama
url = http://localhost:11434/v1/chat/completions
api_key =
model = qwen3
thinking = false
timeout = 60000
max_retries = 2
retry_delay_ms = 250

Instructions, Plugins and Skills

Workspace.instructions specifies an optional UTF-8 instruction file. The root-level file is included with every request. When modifying nested files, load_project_instructions locates relevant instruction files by traversing from the workspace root down to the target directory. Instructions closer to the target refine or override conventions for that subtree. Leave the setting empty to disable project instructions entirely.

Plugins.directories accepts a comma-separated list of absolute or installation-relative paths to personal plugin directories. Each specified directory must already exist.

With Plugins.lazy_loading enabled, only the comma-separated Plugins.core set and search_plugins are initially exposed to the model. Plugin manifests form a searchable index; matching tools are activated for the model's next response. The interactive /tool command can still invoke any installed plugin directly.

Plugins.worker_thread = true runs plugin handlers serially in one persistent Tcl worker thread. The main thread retains tool metadata, validation, approvals, model coordination, and Tk state. This keeps the event loop responsive but does not provide operating-system isolation.

Skills.directories accepts a comma-separated list of personal skill directories. Skill names and their trigger descriptions are included in the system prompt; full instructions are loaded only when the model invokes load_skill. The built-in skills/ directory is always loaded; additional personal skill roots can be placed anywhere and are specified via Skills.directories.

Notes for Windows users

Use forward slashes for absolute INI paths, for example D:/projects/client.

Themes

Set GUI.theme_package to your ttk theme package name and GUI.theme to the desired theme. Place the package in lib/. Leave both empty for the system default.

Extra notes (need editing)

Executables.fossil configures one trusted executable name or absolute path for every bundled Fossil plugin. The default fossil resolves through PATH. On Windows, a full path may be written as C:/Tools/Fossil/fossil.exe.

Danger: this is not a safe agent. The default direct runner executes AI-created Tcl with the same operating-system permissions as the user. It can read, modify, or delete accessible files, start processes, access the network, and inspect environment variables. Enable it only if you understand the consequences and maintain recoverable backups or version control.

run_tcl_file accepts only an approved workspace-relative Tcl file and enforces time/output limits, but direct execution provides no OS isolation. Every execution receives a separate approval; “All for session” does not apply. Platform-specific isolation belongs in optional plugins, such as Bubblewrap on Linux or jails on FreeBSD. Set Runner.enabled = false to remove execution entirely.

Enable Runner.project_tests_enabled to expose run_project_tests. Its executable and Tcl-list arguments come only from trusted configuration; the model supplies no command fields. The profile uses the same backend and always requires separate approval.

Run the agent

Interactive CLIshell
tclsh ./main.tcl

Responses stream to the terminal in real time, and conversation history persists across restarts.

One shotshell
tclsh ./main.tcl "Explain the plugin architecture."

One-shot mode is stateless and prints a single complete response to standard output and exits.

GUIshell
tclsh ./gui.tcl

Launch the graphical interface.

The GUI provides a visual chat interface with theme support, a dark-mode toggle, and incremental native-Tk Markdown styling for assistant responses. Markdown, HTML, links, and code remain inert and are never executed or opened automatically.
