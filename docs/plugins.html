About plugins

Plugins give the model small, explicit capabilities. Tcl keeps handlers compact, while the manifest provides the searchable description, validated argument contract, platform requirements, and permission level.

See the separate bundled plugin catalog for the tools included with OODZ Agent.

Directory layout

Place each plugin in one direct child directory of a configured plugin root.

plugins/ └── my_tool/ ├── plugin.ini └── plugin.tcl

Discovery is deterministic. Nested plugin directories are not recursively registered.

Manifest

The manifest is the contract between the handler, registry, and model.

plugin.iniini
[plugin]
name = my_tool
description = Explain clearly when the model should use this tool.
category = filesystem
keywords = inspect,file,workspace
platforms = linux,freebsd,windows
requires = optional-helper
permission = read
entrypoint = plugin.tcl
handler = ::plugins::my_tool::execute
parameters = {"type":"object","properties":{},"required":[],"additionalProperties":false}

[settings]
endpoint = https://service.example
description, category, and keywords
Form the lazy-loading search index. Describe the capability and its trigger precisely.
parameters
A JSON Schema object validated before the handler runs and shown to the model.
permission
read runs without write approval; write requires explicit approval.
platforms
Accepts all, linux, freebsd, and windows.
requires
Executables required everywhere. Use requires_linux, requires_freebsd, or requires_windows for platform-specific dependencies.
[settings]
Trusted plugin-owner configuration passed to the handler but omitted from model-visible definitions.

Plugin names must be globally unique. Unsupported plugins remain indexed as unavailable and are not exposed to the model.

Tcl handler

plugin.tcltcl
namespace eval ::plugins::my_tool {}

proc ::plugins::my_tool::execute {workspaceRoot arguments settings} {
    return "Tool result"
}
workspaceRoot
The absolute configured project root. Resolve model-selected paths through the shared confinement helpers.
arguments
A Tcl dictionary that already conforms to the manifest JSON Schema.
settings
Private values from the optional [settings] section.

Return concise results. Never return credentials or private settings to the model.

External processes

Plugins that launch an executable should call PluginSupport::runConfiguredCommand rather than Tcl exec. The shared runner applies the workspace working directory, timeout, output limit, structured result, and Stop-button cancellation. Arguments are passed directly without a command shell.

Safety boundary

  • Confine model-selected filesystem paths to the configured workspace.
  • Use named read-only roots for reference source outside the workspace.
  • Classify externally visible or potentially mutating actions as write.
  • Keep command names and dangerous flags under plugin-owner control.
  • Review installed Tcl plugins as trusted local code.
  • Timeouts and approvals are controls, not an operating-system sandbox.
