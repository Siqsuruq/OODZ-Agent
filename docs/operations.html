Persistent history

Interactive conversations are stored in .oodz/history.json. The store is versioned, UTF-8 encoded, atomically replaced, and owner-readable where the platform supports permissions.

History is loaded on startup and saved only after successful turns. Run /new to clear memory and remove the stored file. One-shot commands do not use history.

Diagnostics

Technical logs are written to .oodz/oodz.log instead of the conversation. Use /logs for the latest 20 entries in the terminal, or View → Logs in the GUI for a scrollable, severity-filtered viewer with manual and automatic refresh. Provider finish reasons are recorded; an output-limit finish is reported as truncation rather than successful completion. When the provider reports output-token usage, the GUI shows the latest generation rate and a weighted overall tokens-per-second rate. OODZ explicitly requests usage in Ollama streams; responses that still omit it are excluded.

Separate terminalshell
tail -f .oodz/oodz.log

Actionable CLI errors and write approvals remain visible in the main terminal.

Troubleshooting

Empty streaming response

The client automatically retries once without streaming. Inspect /logs if the buffered request also fails.

No terminal colors

Ensure output is attached to a TTY, TERM is not dumb, and NO_COLOR is unset. Windows uses ASCII borders for CMD and PowerShell compatibility while retaining UTF-8 model output.

Windows path reports that it escapes its root

Use the current release, which compares normalized path components on Windows. Write INI paths with forward slashes, for example D:/projects/app. Workspace.instructions must be a filename relative to the workspace, such as AGENT.md.

Missing configuration or API key

Copy conf/conf.example.ini to the ignored conf/conf.ini, restrict it to your user, and set LLM.api_key there. Never paste the real value into logs or documentation.

Current limits

  • History compaction is deterministic and extractive; it preserves requests, answers, and tool names but does not ask a model to reinterpret older work.
  • The complete stored history can continue growing on disk.
  • Provider adapters currently support DeepSeek and local Ollama; other APIs may require an adapter.
  • JSON, YAML, and SQLite configuration backends are experimental and unsupported.
  • Plugin Tcl code and the direct process runner are not OS-sandboxed and must be treated as trusted, potentially dangerous code.
